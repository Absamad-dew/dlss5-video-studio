# Проверка оптимизаций V22 — 4 сентября 2026

Обычная запись H.264/H.265 теперь передаёт NV12-текстуры непосредственно из D3D12 в NVENC. На CPU поступает только сжатый поток; FFmpeg собирает MP4 без повторного кодирования. Модель, разрешение, частота depth, motion, QP и temporal history намеренно не упрощались.

## Что исправлено

- Четыре GPU-слота NVENC с явными input/output fences, map/unmap и дренированием в конце. Драйвер загружается из System32, без дополнительной DLL в portable.
- Auto при ошибке инициализации возвращается к FFmpeg NVENC **до первого кадра**. Прерывание или ошибка в середине не маскируются повторным запуском. Запись с окном preview и промежуточная чанковая обработка сохраняют прежний путь; realtime ничего не кодирует.
- Старый FFmpeg-путь не размечал входные NV12-кадры как BT.709/tv. В FFmpeg 9 журнал показал `YUV color matrix differs for YUV->YUV, using intermediate RGB to convert`. Добавлена входная разметка: ненужная CPU-конверсия и повторное изменение цвета устранены. Поэтому результат V22 не обязан побайтно совпадать с V21.1.
- Полноразмерные color/depth/motion/bias upload-буферы нужны только синтетическому прогреву. Три неиспользуемых комплекта больше не создаются; единственный рабочий освобождается после GPU fence. Это убирает приблизительно 183 МиБ при 1440p и 411 МиБ при 4K из постоянных upload-аллокаций обоих режимов. Это расчёт размеров ресурсов, не измерение всей VRAM процесса.
- Успешный realtime-run явно возвращает код 0: больше не наследует старый код служебного native-вызова после выдачи `STUDIO_RESULT status=ok`.

## Измерения на RTX 4060 Laptop

CoreBroker: 8 физических / 16 логических CPU, L3/CCD с logical 16–31, exclusive, питание от сети, без смены power profile, один прогрев и три повтора каждой версии. Тест: 120 настоящих кадров 2560×1440 из локального видео, 25 FPS, H.265 P1/LL, QP 18; нейтральные motion/depth для изоляции native-доставки. Генерация guides и декодирование исходника в это измерение **не входят**.

Однокадровый H.264 drain также сохранил точные пиксели и длительность 0,04 с.

Полная запись реального 4K-исходника в 1440p, Fast, 240 кадров: 22,86 с / 10,50 FPS с подготовкой guides, загрузкой моделей и звуком. Ограничение этого фрагмента — depth/motion, 13,76 FPS. Выход: ровно 240 кадров, 9,60 с, HEVC Main и AAC; весь файл декодирован без ошибок.

Realtime, native-разрешение, без FG: 1440p — 240 кадров, 24,962 FPS вывода из 25 FPS источника, 0 buffer underruns; 1080p — 120 кадров, 24,944 FPS, 0 underruns. Это короткие проверки вывода, не длительная гарантия A/V-синхронизации. В одном 1080p запуске был выброс инициализации ReShade до ~22 с; он не скрыт из end-to-end времени.

## Проверка качества

`tests/test-direct-nvenc.ps1` сохраняет точные несжатые NV12-плоскости из того же GPU-run и кодирует их эталонным FFmpeg с одинаковыми настройками. `tests/compare-video-frames.ps1` сравнивает декодированные пиксели каждого кадра, PTS/DTS, длительность, разрешение и цветовую разметку без ресайза и коррекции FPS.

- H.265 1440p, 120 кадров: точное совпадение с кодированием тех же GPU-кадров.
- H.265 4K, 30 кадров: точное совпадение.
- H.264 1080p, 120 кадров: точное совпадение после согласования размера DPB и VUI.
- Раздельные запуски полного NGX-пути не объявляются побитно одинаковыми: в A/B 1440p найдены малые отличия после кадра 58 (PSNR 56,50 dB), хотя изолированный encoder-тест совпадает. Алгоритм рендеринга не менялся.
- Прежний `native-pipe-bench/input.nv12` является синтетическим одноцветным fixture. Его результаты нельзя использовать как доказательство качества на настоящем видео.

Для ручной диагностики runner принимает `-RecordingEncoder Auto|Ffmpeg|D3D12`; в отчёте записывается фактический backend и fallback. `--nvenc-reference` предназначен только для QA: он намеренно возвращает readback и не должен использоваться в замерах ускорения.

## Первичные источники

- [NVIDIA NVENC programming guide 13.1](https://docs.nvidia.com/video-technologies/video-codec-sdk/13.1/nvenc-video-encoder-api-prog-guide/index.html): D3D12 ресурсы и синхронизация.
- [NVENC header 13.0.19.0](https://github.com/FFmpeg/nv-codec-headers/tree/n13.0.19.0): актуальный контракт mapped D3D12 handles; установщик проверяет SHA-256.
- [FFmpeg 9 NVENC implementation](https://github.com/FFmpeg/FFmpeg/blob/n9.0/libavcodec/nvenc.c): QP, DPB, VUI и параметры P1/LL.

Тесты видео и GPU выполнялись только на ноутбуке. На RTX 5080 разрешены доставка обновления и проверка файлов, но не производительные тесты в этой итерации.
